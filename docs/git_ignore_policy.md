# Git Ignore Policy

## Purpose

This repository keeps reviewable source, compact configurations, tests, plans,
and curated Markdown reports in Git.  It does not keep files that EDA tools,
simulators, or Python recreate from those inputs.  Ignoring an artifact only
changes Git status; it never deletes the local artifact or changes a design.

## Current Rules

The root `.gitignore` has intentionally narrow rules for tool products written
at the repository root:

- `alib-*/` is the Design Compiler analyzed-library cache.  It is tied to the
  installed library and tool version and is regenerated by the tool.
- `command.log` and `lc_shell_command.log` are local command transcripts.
- `default.svf` is a Formality/Design Compiler guidance product, not RTL or a
  reviewed equivalence constraint.
- `ucli.key` is a simulator session key with no source-level meaning.

The `rtl/cnn_monitor/.gitignore` owns the CNN measurement boundary.  Its
`/runs/**` rule excludes VCS executables, compiler databases, VCD/SAIF files,
mapped netlists, synthesis reports, generated vectors, and other evidence
products below a task-specific run directory.  Source RTL, testbenches,
scripts, small JSON configuration, and the maintained reports live outside
that directory and remain versionable.

Existing repository-wide rules also exclude Python caches, test caches,
checkpoints, TensorBoard streams, simulator waveform/listing products, and
generated TCN and delay-chain run data.  The rules are path-specific where
possible; no catch-all `*.log`, `*.svf`, `*.json`, or `*.v` rule is used, since
those suffixes can also describe intentional design inputs or reports.

The only Phase-3 exception is the final wide-range code curve and its summary
under `delay_chain/phase3/runs/wide_range_final/`.  They are small, curated
evidence needed to reproduce the published 0.70--1.10 V conclusion; scenario
directories, generated decks, listings, waveforms, command logs, and all
screening outputs remain ignored.

## Verification And Maintenance

Before a commit, inspect the effect with:

```bash
git status --short
git check-ignore -v <artifact-path>
git diff --check
```

`git check-ignore -v` identifies both the matching rule and its source file.
If an ignored output becomes a required, reviewed deliverable, move or export
the compact curated form outside the run/cache directory rather than weakening
the rule for all generated data.  Conversely, add a new ignore entry only when
the exact file class is reproducible and is not an input required to rebuild,
verify, or review the design.
